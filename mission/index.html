P1 Production C++ Real-Time — Gap #1 THÁNG 1–2 ▼
"Bạn đã biết C++ đủ để viết firmware ESP32. Cái thiếu là production C++: class với constructor/destructor đúng, smart pointer, real-time control loop." — Gap thật, không phải "học C++ từ đầu". Rủi ro thật: bạn nói đã đọc code có shared_ptr/unique_ptr nhưng chưa tự viết. P1T1 dưới đây ép bạn tự viết lần đầu — nếu sanitizer pass ở checkpoint P1T1.5, bạn đã sẵn sàng cho rclcpp executor (P1T2). Nếu chưa, dừng ở đó và lặp lại P1T1 với scope nhỏ hơn — KHÔNG tiến sang P1T2 khi chưa qua checkpoint.
  • Rewrite obstacle-avoidance node (HG-Dagger project) sang C++ real-time
    Lấy chính project "more-than-imitation-learning" — port phần inference loop từ Python sang C++ với fixed-rate control loop (1kHz), không dynamic allocation trong loop. Benchmark latency trước/sau. Thiết kế bắt buộc: ít nhất 1 class tự viết (ví dụ PolicyRunner) có constructor/destructor rõ ràng, quản lý 1 resource (model handle, file, hoặc buffer) qua std::unique_ptr — không dùng raw new/delete. Đây là lần đầu tự viết pattern này, không phải đọc lại code mẫu.
    CRITICAL
  • ⛔ GATE — Checkpoint trước khi vào P1T2
    Chạy AddressSanitizer trên class từ P1T1 — phải sạch (0 leak, 0 use-after-free). Tự giải thích bằng lời (ghi vào Notes, English): "constructor làm gì, destructor làm gì, vì sao dùng unique_ptr ở đây thay vì raw pointer". Nếu PASS cả 2 → tick xong, sang P1T2. Nếu KHÔNG → đọc "C++ Concurrency in Action" chương 1 + LearnCpp.com phần Smart Pointers (link Resources), sửa lại P1T1, thử lại checkpoint — không cần unlock task mới, lặp ở đây.
    CRITICAL
  • Học rclcpp real-time patterns: lock-free queue, executor, callback groups
    Đọc source code rclcpp executor + ros2_control. Viết 1 node C++ dùng MultiThreadedExecutor đúng cách, đo jitter bằng `ros2 topic hz`. (Yêu cầu: đã pass GATE P1T1.5 — node này sẽ dùng lại class PolicyRunner qua shared_ptr giữa các callback, nên nếu chưa vững unique_ptr/shared_ptr ở bước trước, phần này sẽ rất khó debug.)
